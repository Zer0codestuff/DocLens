# DocLens project context

## Purpose and architecture

DocLens is a native macOS app that extracts PDF tables into editable datasets with source evidence, review state, corrections, and export. `SPECIFICATIONS.md` is the product specification; `README.md` describes features and usage.

- `Sources/DocLensCore`: engine-independent model, geometry (PDF points, rotation, crop boxes, image pixels), extraction engines (PDF text layer, Vision OCR + layout, Vision `RecognizeDocumentsRequest`, optional Docling worker over JSON lines), layout analysis, normalization, checks, SQLite store with versioned extractions and correction carry-over, exporters (CSV, XLSX, JSON), recipes, corpus generator, and benchmark.
- `Sources/doclens`: CLI over the same core.
- `App/Sources`: SwiftUI app with an AppKit bridge for PDFKit (`PDF/PDFPane.swift`) and the grid. `Model/AppModel.swift` holds app state; the app is the only database writer.
- `Tests/DocLensCoreTests`: swift-testing suites for normalization, geometry, workflow, exports, and recipes.

Chosen without a separate confirmation (the user asked to proceed without questions; revisit if needed):

- Primary engine: `Automatic`, which uses the text layer when the region has readable text and Vision Document Structure otherwise. Docling is optional and not bundled. Evidence: `Evaluation/docling-comparison.md`.
- Minimum macOS 26 (Vision `RecognizeDocumentsRequest`), Apple Silicon.
- Storage: a library directory (`~/Library/Application Support/DocLens/Library`) with `library.sqlite` and read-only sources named by SHA-256. `DOCLENS_LIBRARY` overrides it.
- Xcode project generated by XcodeGen from `project.yml`; ad-hoc signed, sandbox off.

## Run, build, and test

```sh
swift build                      # core and CLI
swift test                       # 35 tests, a few seconds once Vision is warm
swift test --filter WorkflowTests
xcodegen generate                # after adding or removing app files
xcodebuild -project DocLens.xcodeproj -scheme DocLens -configuration Debug -derivedDataPath .build/xcode build
open .build/xcode/Build/Products/Debug/DocLens.app
swift run doclens corpus /tmp/corpus && swift run doclens bench /tmp/corpus --engines text,ocr,vision,auto --out Evaluation/benchmark.md
swift run doclens add /tmp/corpus/*.pdf --library /tmp/lib --detect   # seed a test library
```

Docling benchmark: create a Python environment with `docling`, then `doclens bench <corpus> --engines docling --python <env>/bin/python`.

There are no UI tests. The UI was checked by hand with real mouse and keyboard input and window screenshots.

## Project preferences and constraints

- Write source code, identifiers, UI copy, documentation, and metadata in English.
- Do not use em dashes in any authored text. Write dash characters in code as Unicode escapes.
- Keep the interface native, minimal, spacious, and usable with the keyboard.
- Keep document processing local and usable offline after explicit resource installation.
- Preserve original PDFs, extracted text, and user corrections separately.
- Keep source references, automatic checks, and user review as distinct concepts.
- Record engine versions and configuration so extraction results can be reproduced.
- Confirm important unresolved product or implementation choices before material changes.
- Update this file after meaningful work and tell the user exactly what changed.
- If GitHub work is requested, use Zer0codestuff as the sole commit author and follow the user's branch and pull-request workflow.

## Known issues and next steps

- The corpus is synthetic. Build the roughly 20-document annotated corpus of real reports from the specification, then set quality thresholds.
- No task-time study with users yet (acceptance criterion 9).
- Not packaged for distribution: no Developer ID signing, notarization, or sandbox.
- Docling starts a new worker per extraction (about 2 s of setup each) and needs 1.5 to 2.7 GB of memory. If real scans justify it, keep a warm worker or bundle it for scans only.
- Vision OCR + Layout is weak on borderless and dense tables. `Automatic` uses it only as a fallback when its first engine finds no table.
- PDFKit reads `PDFView.document` from background queues during page analysis. Do not override `document` in `DocLensPDFView`; a main-actor override crashes on scanned pages.

## Do not

- Do not invent extracted values, source highlights, benchmark results, or calibrated confidence percentages.
- Do not mark data as user-reviewed because an automatic check passed.
- Do not overwrite source documents or silently discard corrections during re-extraction.
- Do not add cloud processing, accounts, document chat, or model training to the first release without an agreed scope change.
- Do not require end users to install Python manually for a packaged application.
- Do not publish, create a remote repository, or deploy the project without a user request.
